# Training stack for the predictive layer, plus the inference stack it
# builds for. Kept SEPARATE from requirements.txt: training is a batch
# activity on the RTX 5090 and must not become a runtime dependency of the
# trading system. JARVIS has to start and trade with none of this
# installed.
#
# Install:
#     pip install -r requirements-ml.txt \
#         --extra-index-url https://download.pytorch.org/whl/cu128
#
# --extra-index-url, NOT --index-url. The CUDA index is a PARTIAL index: it
# carries the torch wheels and not numpy or openvino. Replacing PyPI with
# it leaves the rest of this file unresolvable.
#
# The CUDA 12.8 index is needed at all because the RTX 5090 is Blackwell
# (sm_120), and the default PyPI wheels do not carry that architecture —
# torch imports fine and then reports no usable device, which reads like a
# driver problem rather than a wheel problem.

# ── Inference (CPU / Intel NPU) ──────────────────────────────────────────
# Split into its own file because CI has no GPU and cannot resolve the
# torch pin below, which is why the ML extras silently never installed
# there. Everything in it comes from PyPI and can be installed alone:
#     pip install -r requirements-inference.txt
-r requirements-inference.txt

# ── Offline analysis ─────────────────────────────────────────────────────
# Pinned to the last releases that support numpy 1.26.4 — see the pin note
# in requirements-inference.txt. scipy >= 1.15 requires numpy >= 2.0 and
# would drag the whole numerical foundation with it.
#
# All 1,341 tests happened to pass on numpy 2.5.2 when this was discovered,
# but tests do not cover every path, and that is not a risk worth taking
# for a dependency used only by offline training.
scipy<1.15
scikit-learn<1.6

# ── Training (RTX 5090) ──────────────────────────────────────────────────
# Never the NPU: it is an inference device.
torch==2.11.0+cu128
